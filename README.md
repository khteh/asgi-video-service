# STEM Explainer Video Service (ASGI)

An ASGI service that turns a learner's STEM question into a
short, narrated explainer video. Built so the _generation backend_ is a
plug-and-play boundary: a fully self-contained **simulated** provider ships
by default (no API key, real slides + real narrated audio + real MP4), and
a **real AI** provider is a clean adapter interface away.

This project is generated using Claude desktop in multiple rounds of prompts.

## Prompts

```
Create a Python service with an API endpoint where a client can request a STEM concept explanation video. STEM stands for Science, Technology, Engineering and Mathematics. The service must be designed and implemented using asynchronous video-generation flow. Here are the requirements for the application:

1. Please use uv package manager.
2. Use Python Quart ASGI framework.
3. Use Python Anycorn ASGI web server.
4. Clear service design which enables plug-and-play of both simulated generation and real AI/video-generation providers.
5. src/ folder should contain the application source code.
   - src/view/static contains the static resources of the web interface.
     - src/view/static/css contains the CSS
     - src/view/static/images contains the images. For example, favicon.png and logo.png.
     - src/view/static/js contains the javascript code.
   - src/view/templates contains the view templates used by the Quart framework.
6. test/ folder should contain the tests.
7. output/ folder should contain the outputs of the application. For example, the generated videos and the job statuses.
8. a way for learners to submit their query of the topic they are interested in. Here are some examples of the questions that the application must be able to answer:
   i. How does the pH scale work?
  ii. Why do atoms form covalent bonds?
 iii. What is the difference between ionic and covalent bonding?
9. a way to list requested videos or jobs
10. a visible status for each requested video or job
11. a way to retrieve or open a completed video explanation artifact
12. visual content and audio for the explanation, similar to how a normal short educational video would feel
13. a clear backend boundary for job state, generation logic, persistence, and artifacts
14. Limit video length to 90 seconds.
15. Use 4K video resolution.
16. Use 60 fps.
17. Use Nvidia GPU for hardware acceleration.
18. The voice of the video should be as authentic and real as possible as compared to monotonic synthetic voice.
19. Scale the number of slides generated according to difficulty level.

Failure cases which should NOT fallback to simulated generation but to return a proper error status and message to the user immediately without creating any job:
1. Invalid query string even if the length is right. For example:
   i.  ~!@#$
  ii. 12345
 iii. "     "
2. Questions which do not make any semantic sense or not being relevant to STEM topic.
3. No network or improper API key in "ai" generation mode.
```

## Project layout

```
src/
  api/                JSON API routes (Quart Blueprint)
  web/                HTML view routes (Quart Blueprint)
  domain/              models.py (Job, JobStatus, DifficultyLevel, GenerationResult),
                        errors.py (ServiceError hierarchy)
  validation/           rule_based.py (offline structural + keyword check),
                        llm_validator.py (optional LLM refinement),
                        composite.py (combines the two)
  generation/
    base.py             VideoGenerationProvider protocol - the plug-and-play boundary
    registry.py         maps a provider name -> configured provider instance
    simulated/          offline provider: slides.py (content), renderer.py (Pillow
                        slide images), tts.py (edge-tts narration),
                        video_builder.py (ffmpeg assembly, NVENC/CPU, duration cap)
    ai/                 generic/vendor-agnostic real-provider HTTP adapter
  jobs/                service.py (validate -> preflight -> create job),
                        worker.py (async queue consumer that runs generation)
  persistence/          job_store.py (JSON-file job state), artifact_store.py
                        (locates video/thumbnail files)
  view/
    static/{css,images,js}
    templates/
  config.py             environment-driven Settings
  main.py                Quart application factory (composition root)
test/                    pytest suite (see Testing below)
output/
  jobs/<job_id>.json     job status - one flat file per job, named by job id
  videos/<job_id>.mp4    the finished video - one flat file per job, named
                        by job id, directly under videos/
  videos/<job_id>/       per-job scratch dir: thumbnail.png, plus the
                        intermediate slides/ and audio/ the simulated
                        provider rendered on the way there
```

## Setup

Requires Python >=3.11, [uv](https://docs.astral.sh/uv/), and `ffmpeg` on `PATH`
(`ffmpeg -version` to check). For real NVIDIA acceleration, an NVENC-capable
GPU + driver; without one the service automatically falls back to software
encoding (libx264) - it still works, just without hardware acceleration.

```bash
uv sync --extra ai
cp .env.example .env   # optional, defaults work out of the box
uv run anycorn src.main:app --bind 0.0.0.0:8000
```

Then open http://localhost:8000.

## Testing

```bash
uv run pytest
```

The suite is fast and network-free by design: `test/conftest.py` provides a
`FakeProvider` that job-service/API tests use instead of the real simulated
provider, so most of the suite needs neither ffmpeg nor edge-tts/network
access. Two exceptions:

- `test/test_video_builder.py` runs real ffmpeg (it's a requirement of the
  service anyway) to prove the 90s hard cap and NVENC/CPU fallback actually
  work - it auto-skips if `ffmpeg` isn't on `PATH`.
- The _simulated provider's own_ end-to-end narration path needs outbound
  network access to edge-tts's speech endpoint; that's exercised by running
  the app for real, not by the test suite (to keep tests hermetic).

## API

```
POST /api/jobs
  { "query": "How does the pH scale work?",
    "difficulty": "beginner" | "intermediate" | "advanced",   # optional, default "intermediate"
    "provider": "simulated" | "ai" }                          # optional, default "simulated"
  -> 201 {job}   |   400/422/503 {"error": {"code", "message"}}   (no job created on error)

GET  /api/jobs                 -> 200 { "jobs": [ {job}, ... ] }
GET  /api/jobs/<id>             -> 200 {job}   |   404
GET  /api/jobs/<id>/artifact    -> the MP4 (or 404 until completed)
GET  /api/jobs/<id>/thumbnail   -> a PNG poster frame (or 404 until completed)
```

A `{job}` looks like:

```json
{
  "id": "…",
  "query": "How does the pH scale work?",
  "difficulty": "beginner",
  "provider": "simulated",
  "status": "pending | generating | completed | failed",
  "progress": 0.0,
  "stage": "queued",
  "created_at": "…",
  "updated_at": "…",
  "error_message": null,
  "error_code": null,
  "result": null
}
```

`result` (once `status` is `completed`) carries `video_path`,
`duration_seconds`, `slide_count`, `width`, `height`, `fps`, `provider`,
`narration_voice`, and `hardware_acceleration` (`"nvenc"` or `"cpu"`).

## Configuration

All API keys are set in `.env` locally or through secrets when deployed in k8s.

- `AI_VIDEO_API_KEY` / `AI_VIDEO_BASE_URL` - point the `ai` provider at a
  real text-to-video service (see "Adding a real AI provider" below).
- `LLM_VALIDATION_API_KEY` (or `ANTHROPIC_API_KEY`) - optional; enables the
  LLM-based query validator refinement instead of the rule-based-only check.

See `asgi-video-service_config.json.example` for the full list with defaults. The highlights:

- `GENERATION_PROVIDER` - default provider when a request doesn't specify one.
- `MAX_VIDEO_SECONDS` / `VIDEO_WIDTH` / `VIDEO_HEIGHT` / `VIDEO_FPS` - the
  hard encode constraints.
- `NVENC_MODE=auto|on|off` - `auto` probes ffmpeg for a _usable_ NVENC
  encoder (not just one that's compiled in) and falls back to libx264.
- `TTS_VOICE` - any edge-tts neural voice (`uv run edge-tts --list-voices`).

### Full parameter reference

Every field below is read once, in `src/config.py::Settings.from_env()`,
from `/etc/asgi-video-service_config.json` (see
`asgi-video-service_config.json.example`) - except the two marked **env
var**, which come from the process environment (`.env` locally, k8s secrets
in prod) instead, the same way `AI_VIDEO_API_KEY` already was. A few keys
are read with no fallback at all (marked **required**) - omitting them from
the config file raises `KeyError` at startup; everything else has a real
default and can be left out entirely.

#### Core / logging

| Key              | Type   | Default                                                 | Notes                                                                                                                                                                                           |
| ---------------- | ------ | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ENVIRONMENT`    | string | _(required)_                                            | `"development"` logs to `/var/log/asgi-video-service/log` (mode `w`, truncated on every start); anything else logs there via a daily-rotating handler (3 backups kept) plus stdout.             |
| `LOGLEVEL`       | string | _(required)_                                            | Passed straight to `logging.basicConfig(level=...)` - e.g. `"DEBUG"`, `"INFO"`, `"WARNING"`.                                                                                                    |
| `SECRET_KEY`     | string | `"you-will-never-guess"`                                | Quart's session-signing key. Key must be present in the file; an empty/falsy value falls back to the default.                                                                                   |
| `JWT_SECRET_KEY` | string | a random 64-byte hex string, generated fresh at startup | Only used if present **and** at least 64 characters; otherwise a new one is generated every startup, so anything signed with it won't survive a restart - set it explicitly for a stable value. |
| `OUTPUT_DIR`     | string | `"output"`                                              | Root of `output/jobs/` (status) and `output/videos/` (video/thumbnail/scratch). Key must be present; falsy value falls back to the default.                                                     |

| `TTS_VOICE`         | string | _(required)_ | Any edge-tts neural voice name (`uv run edge-tts --list-voices`).                                                                    |

#### Worker, retries and timeouts

| Key                       | Type  | Default | Notes                                                                                                                                                                                                                                                                                                                        |
| ------------------------- | ----- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WORKER_CONCURRENCY`      | int   | `3`     | Number of concurrent job-worker tasks (`JobWorker`).                                                                                                                                                                                                                                                                         |
| `MAX_JOB_ATTEMPTS`        | int   | `3`     | On startup, a job left `pending`/`generating` by a process that exited (crash/restart) is re-enqueued - up to this many total attempts (`Job.attempt_count`, persisted across restarts). Beyond that, `JobWorker.recover_orphaned_jobs` gives up and marks it `failed` (`max_retries_exceeded`) instead of retrying forever. |
| `FFMPEG_TIMEOUT_SECONDS`  | float | `120.0` | Ceiling on any single ffmpeg subprocess call (`video_builder.py`) - a per-slide encode or the final concat. A wedged process is killed and the job fails, instead of its worker slot hanging forever.                                                                                                                        |
| `FFPROBE_TIMEOUT_SECONDS` | float | `30.0`  | Same idea, for the `ffprobe` calls that measure narration/video duration.                                                                                                                                                                                                                                                    |
| `TTS_TIMEOUT_SECONDS`     | float | `30.0`  | Ceiling on a single edge-tts narration-synthesis call (`tts.py`).                                                                                                                                                                                                                                                            |

set in the same JSON file - `create_app()` loads the whole file into
Quart's own `app.config` via `app.config.from_file(...)`, independently of
the `Settings` fields above.

## How a video gets made (simulated provider)

1. **Validate** the query (`src/validation`) - structural check, then
   relevance check (or an LLM call, if configured).
2. **Preflight** the chosen provider (a no-op for `simulated`; for `ai`,
   checks the API key and reaches the upstream host).
3. Only now is a `Job` created and persisted as `output/jobs/<id>.json`.
4. A worker picks the job off the queue and asks the provider to generate:
   - **Content**: `slides.py` picks from a small curated knowledge base for
     the spec's example topics (pH scale, covalent bonds, ionic vs.
     covalent), or falls back to a generic structured template built from
     the query for anything else. Slide _count_ scales with difficulty
     (4 / 6 / 9) by evenly sampling a full outline, always keeping the
     intro and the "key takeaway" summary.
   - **Visuals**: `renderer.py` draws each slide with Pillow (title,
     bullets, a decorative motif, progress dots) at the target resolution.
   - **Narration**: `tts.py` synthesizes each slide's narration with
     edge-tts (free neural voices - no API key, needs network).
   - **Assembly**: `video_builder.py` measures each narration clip's real
     duration, speeds up narration (up to ~1.5x) and/or proportionally
     compresses slide timing if needed so the video _never_ exceeds the
     90s cap, then encodes with ffmpeg at the target resolution/fps,
     preferring NVENC when a GPU is actually usable.
5. The job is marked `completed` with a `GenerationResult`, or `failed` with
   a clear error message - never left stuck.

**Honest limitation**: the simulated provider's content for topics outside
the curated set is a generic template, not researched writing - producing
genuinely novel, accurate STEM content for an arbitrary question is exactly
the job a real AI provider is meant to take over. The pipeline around it
(validation, difficulty scaling, timing/duration enforcement, encoding) is
fully real and provider-agnostic either way.

## Adding a real AI provider

Implement `VideoGenerationProvider` (`src/generation/base.py`): a
`preflight()` that fails fast on a bad/missing key or unreachable host, and
a `generate()` that writes an MP4 to the given path and returns a
`GenerationResult`. `src/generation/ai/provider.py` already has a generic
submit/poll/download HTTP client wired to `AI_VIDEO_API_KEY` /
`AI_VIDEO_BASE_URL` - adjust the request/response shape in `_submit`/
`_poll`/`_download` to match your chosen provider's actual API, or swap the
class out entirely and register it in `src/generation/registry.py`.
Nothing outside that one file needs to change.

## Chrome browser

- Close ALL chrome browser (both tabs and windows)

- Generate TLS certificate fingerprint:

```
$ fingerprint=`openssl x509 -pubkey -noout -in /tmp/server.crt |
        openssl rsa -pubin -outform der |
        openssl dgst -sha256 -binary | base64`
```

- Start Chrome browser with QUIC protocol for HTTP/3:
- `$1` is URL. For example: `https://localhost:4433`

```
$  /opt/google/chrome/chrome --disable-setuid-sandbox --enable-quic --ignore-certificate-errors-spki-list=$fingerprint --origin-to-force-quic-on=${1#*//} $1
```
